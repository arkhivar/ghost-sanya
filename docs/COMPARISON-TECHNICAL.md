# Сравнение жилья: устройство и формат данных

Инструкция для автора находится в [STAY-SNIPPETS.md](STAY-SNIPPETS.md). Этот файл описывает границу между Ghost, HTML-карточкой и JavaScript темы.

## Поток данных

1. Ghost хранит обычные посты. Серверный `#get` в `partials/stays.hbs` получает до 100 опубликованных записей с тегом `stays`, включая теги, и выводит каталог жилья.
2. `partials/stay-row.hbs` передаёт интерфейсу slug, ссылку, заголовок и реальные теги каждой записи.
3. `initSaved()` в `assets/js/index.js` управляет фильтрами и выбранными местами. Выбор хранится под прежним ключом `hainan-atlas:saved` в `localStorage`.
4. Компонент сравнения получает выбранные slug и загружает HTML соответствующих опубликованных постов с того же сайта. Дополнительно данные подгружаются для видимых строк каталога, чтобы показать актуальные название и сводку о кухне.
5. Парсер находит одну таблицу `data-stay-facts="1"` и читает строки по постоянным ключам `data-field`.
6. Таблица на главной показывает объекты в колонках, параметры — в строках. Бухта и тип поступают из Ghost-тегов, остальные характеристики — из HTML-карточки поста.

Это расширение темы. Оно не добавляет произвольные поля в модель Ghost и не выполняет записи в CMS со стороны посетителя. В браузере нет Admin API-ключа, внешнего сервиса извлечения фактов или автоматического вывода характеристик из рассказа автора.

## Контракт HTML, версия 1

В опубликованном HTML должен быть ровно один элемент `<section data-stay-facts="1">`. Внутри — видимый заголовок «Условия проживания» и обычная таблица. Каждая строка в `tbody` имеет постоянный `data-field` и ровно три ячейки:

```html
<section data-stay-facts="1">
    <h2>Условия проживания</h2>
    <table>
        <thead>
            <tr>
                <th scope="col">Параметр</th>
                <th scope="col">Значение</th>
                <th scope="col">Примечание / источник</th>
            </tr>
        </thead>
        <tbody>
            <tr data-field="kitchen">
                <th scope="row">Кухня</th>
                <td>Не уточнено</td>
                <td>Нужно проверить оснащение конкретного номера.</td>
            </tr>
        </tbody>
    </table>
</section>
```

Это сокращённый пример структуры. Для поста используется [полный шаблон](../snippets/stay-facts.html), содержащий все поля:

| Ключ | Содержимое |
| --- | --- |
| `name` | Короткое название для сравнения; полное официальное название при необходимости находится в примечании. |
| `address` | Адрес. |
| `room` | Категория номера / апартаментов. |
| `occupancy` | Размещение гостей. |
| `airport-distance` | Расстояние от SYX с единицами. |
| `airport-time` | Время из SYX с единицами. |
| `kitchen` | Кухня и её оснащение. |
| `price` | Сумма с валютой. |
| `price-basis` | Условия, к которым относится цена. |
| `stars` | Категория объекта со ссылкой на источник. |
| `beach` | Путь к пляжу. |
| `children` | Условия для детей. |
| `pool` | Бассейн и подогрев. |
| `windsurf` | Условия именно виндсёрфинга. |
| `checked` | Дата и область проверки. |

Ключи идентифицируют данные, видимые подписи `th` помогают читателю. Порядок строк в статье не используется как идентификатор. Порядок сравнения задаёт `STAY_FIELDS`: после бухты и типа идут время / расстояние от аэропорта, кухня и цена, затем остальные условия. `name` используется в заголовке колонки, а не отдельной строкой. Значения — текст с уже указанными единицами, оговорками и контекстом. Парсер не конвертирует валюты, не рассчитывает поездку из цены за ночь, не ранжирует отели и не превращает рекламное утверждение в подтверждённый факт.

Неизвестное значение записывается как `Не уточнено`. Оно отличается от `Нет`. У схемы нет отдельного скрытого флага «проверено»: степень уверенности и источник должны быть видны в ячейках. В примечании допускаются обычные ссылки на доказательства. Дубликаты блоков / ключей и изменение числа ячеек нарушают контракт. Не используйте `colspan`, `rowspan`, вложенные таблицы или выполняемый код.

Бухта и тип не входят в список полей: они берутся из тегов `sanya-bay`, `dadonghai`, `yalong-bay`, `haitang-bay` и `apartments` / `hotels`. Это исключает вторую независимую копию данных о принадлежности к фильтрам.

## Выбор и загрузка

`initStayComparison({ section, onRemove })` возвращает объект с методом `update(slugs)`. `section` — раздел жилья; `onRemove(slug)` передаёт удаление владельцу состояния в `initSaved()`. Этот обработчик должен синхронно сохранить новое состояние и вызвать `update()`; компонент не ведёт вторую независимую копию `localStorage`. Переданные slug проверяются по реально выведенным строкам каталога, дубликаты исключаются. Новые добавления ограничены четырьмя вариантами. Если старый список уже содержит больше четырёх доступных записей, он не обрезается: показаны все капсулы, а сравнение недоступно, пока пользователь не уберёт лишние.

Кнопка «К сравнению» в строке меняется на «Выбрано». После выбора появляется панель с названиями мест и счётчиком. «Сравнить выбранные» доступна при двух–четырёх вариантах и раскрывает `#stay-comparison`. После открытия изменение выбора обновляет колонки; удаление до одного варианта заменяет таблицу подсказкой. «Свернуть» скрывает таблицу, сохраняя выбор. Панель сама по себе не открывается при перезагрузке страницы или переходе по якорю.

Используется прежнее хранилище, поэтому ранее выбранные записи, которые ещё есть в каталоге, сохраняются. Локальный выбор относится к конкретному браузеру и origin сайта; он не синхронизируется с Ghost или другими устройствами. При недоступном `localStorage` текущий выбор может работать в памяти открытой страницы, но не гарантирован после перезагрузки.

Загрузка идёт по ссылке поста из каталога, а не по URL, составленному вручную из slug. Допускается только тот же origin; после редиректа origin проверяется повторно. `fetch` использует `credentials: "omit"`: наличие редакторской сессии не открывает для сравнения закрытые характеристики. Таймаут — 15 секунд, предел ответа — 3 000 000 символов. `IntersectionObserver` начинает загрузку, когда строка каталога попадает в область просмотра; для браузера без него предусмотрена проверка видимых строк при прокрутке. Открытие сравнения загружает выбранные записи независимо от их видимости в каталоге.

Только опубликованный HTML записи является источником характеристик. Черновик, изменение локального файла примера или сохранение нового Snippet не меняют таблицу на главной. После редакторской правки нужно сохранить публикацию и перезагрузить главную. Данные уже открытых постов кэшируются в пределах текущей страницы, чтобы повторный выбор не требовал лишней загрузки.

Кэш — `Map` в памяти компонента, по абсолютному URL записи. Он объединяет повторные запросы и хранит результат до перезагрузки страницы; это не `sessionStorage` и не база характеристик в `localStorage`. «Повторить загрузку» заменяет запись в кэше для конкретного объекта. Обновление Ghost в другой вкладке само по себе не инвалидирует этот кэш.

| Состояние | Когда возникает | Отображение |
| --- | --- | --- |
| `loading` | Запрос ещё выполняется. | Загрузка в колонке и строке каталога. |
| `ready` | Распознан корректный блок хотя бы с одним известным полем. | Значения и раскрываемые примечания / источники. |
| `missing` | Нет элемента `data-stay-facts`. | Пояснение об отсутствии таблицы и ссылка на пост. |
| `malformed` | Несколько блоков, неподдерживаемая версия, неправильная структура, повтор поля или ни одного известного поля. | Пояснение о проблеме формата и ссылка на пост. |
| `error` | Сеть, неуспешный HTTP-ответ, таймаут, внешний редирект или превышение лимита размера. | Сообщение об ошибке и кнопка повторной загрузки. |

Пустая ячейка становится `Не уточнено`. Отсутствующий известный ключ также получает это значение, пометку `missing: true` и объяснение, что поле не заполнено. Неизвестные ключи пропускаются и попадают в `warnings`; они не создают новые строки сравнения. Если блок целиком недоступен, ячейки показывают `Нет данных`, а причина указана под названием. Это отличается от авторского `Не уточнено` внутри успешно прочитанной таблицы.

`name` из таблицы обновляет название в строке каталога, заголовке колонки и панели выбора; при неуточнённом названии остаётся заголовок Ghost. `kitchen` формирует сводку в каталоге. Ссылки постов и фильтры при этом не меняются. На главной значения создаются через `textContent`, без вставки HTML из статьи. Парсер убирает из извлекаемого текста `script`, `style`, `template` и `noscript`; ссылки отдельно разрешаются относительно URL поста, допускают только HTTP(S) и не должны содержать логин / пароль. Ссылки берутся из ячеек значения и примечания, повторяющиеся URL объединяются.

Эти ограничения относятся к чтению данных для сравнения. Они не превращают произвольный HTML в самой статье в безопасный формат: в редактор вставляется только наша простая таблица. Публичная запись с таблицей доступна без JavaScript как обычная статья. Интерактивное сравнение требует JavaScript и поддерживаемого экранного режима атласа.

## Редакционный источник и резервные копии

HTML-карточка в Ghost — единственное рабочее место редактирования характеристик. `snippets/examples/` хранит исходные примеры: синхронизации с Ghost у этой папки нет. Обновление шаблона также не обновляет вставленные ранее копии. Для изменения схемы потребуются согласованные правки парсера, шаблона, постов и документации.

Тема в Git не содержит базу Ghost, библиотеку Snippets или пользовательские медиа. Их резервное копирование выполняется отдельно. В репозиторий нельзя добавлять реальные учётные данные, Admin API-ключи, закрытые экспорты и локальную базу. По просьбе владельца каждый локальный коммит нужно сразу отправлять в `arkhivar/ghost-sanya` и проверять успешность push перед следующим коммитом.

## Проверка изменения

1. В опубликованной записи проверьте одну видимую таблицу, все 15 ключей, три ячейки в строке, отсутствие дубликатов и доступность ссылок-источников.
2. На главной выберите два объекта и сопоставьте несколько значений с таблицами постов. Проверьте отдельно название, цену с условиями, кухню, дату проверки и `Не уточнено`.
3. Проверьте пересечение фильтров по бухте / типу, добавление и удаление объектов, максимальное число выбранных мест и сохранение после перезагрузки.
4. Измените одно значение в тестовом посте, сохраните публикацию и обновите главную. Сравнение должно показать новое значение. Не оставляйте тестовые данные в реальном посте.
5. Проверьте понятные состояния для записи без таблицы, некорректного блока и ошибки загрузки. Не подменяйте ошибку неуточнёнными значениями и не используйте фиктивные характеристики.
6. После изменения исходников выполните `pnpm test:ci` и при необходимости `pnpm exec gscan --verbose .`. Собранные `assets/built/` должны соответствовать исходникам.

Новые поля сначала добавляются в схему парсера и общий шаблон; новые редакционные строки без поддержки в коде не становятся параметрами сравнения автоматически. Если каталог вырастет за пределы 100 записей или понадобятся числовая сортировка, актуальные цены, аккаунты и синхронизация выбора, потребуется отдельное расширение архитектуры.
